== Overview

All backend configuration lives in `src/main/resources/application.yml`. There is a single configuration file — environment-specific values are provided via environment variables with defaults for local development.

The frontend API base URL is set in `frontend/src/environments/`.

== Database

[source,yaml]
----
spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/los_db}
    username: postgres
    password: ${DB_PASSWORD:sujan2003}
----

When using the provided Docker Compose setup, the database is on port **5433** and the container maps it to the internal port 5432. Override `DB_URL` if your PostgreSQL is on a different host or port.

Database schema is managed by **Flyway**. Migrations run automatically on startup from `src/main/resources/db/migration/`; Hibernate validates the resulting schema and does not create or update it.

An empty database runs migrations V1 through V10. The staff credentials migration is V8.1 so both V8 changes have distinct Flyway versions; its SQL contents are unchanged.

=== Existing databases

Earlier application versions used Hibernate `ddl-auto: create` or `update`, while the Spring Boot 4 Flyway integration module was absent. The documented application startup therefore created or updated tables through Hibernate without recording Flyway history. Adoption of such a database is explicit: back up the database, stop the application, and confirm that `public.flyway_schema_history` does not exist. Check that the existing schema contains the V1–V9 application tables and columns expected by the current entities, including `loan_application.fineract_loan_id`, and check for duplicate non-null `(tenant_id, fineract_loan_id)` values. Resolve any duplicates against Fineract; migration V10 intentionally refuses to rewrite loan references.

For a verified existing schema without Flyway history, set `SPRING_FLYWAY_BASELINE_ON_MIGRATE=true` for one startup. Flyway records baseline version 9, then runs V10 to create and initialize the mock sequence and add the tenant-scoped unique constraint. Baseline adoption does not replay V1–V9 SQL: SQL-only indexes from those migrations are not added, and V8.1's default staff rows are not inserted. This preserves the existing Hibernate-created database's prior behavior; provision any required staff accounts through the normal administrative process. After successful startup, remove the override; the baseline is recorded in the database. Do not use this override on an empty database or a database whose schema has not been checked.

If `flyway_schema_history` already exists, do not use the baseline override. Inspect its recorded versions before upgrading. In particular, a recorded V8 entry for `create staff credentials` may fail validation after the file is renumbered to V8.1, while a V8 entry for `add fineract client id` remains the current V8 migration. Such histories require an individually reviewed reconciliation plan; do not run `repair` or alter recorded history blindly.

`spring.flyway.baseline-version` defaults to 9 for this adoption path. `spring.flyway.baseline-on-migrate` remains false by default and can be enabled with `SPRING_FLYWAY_BASELINE_ON_MIGRATE` only after the checks above.

== Authentication

[source,yaml]
----
los:
  jwt:
    secret: ${JWT_SECRET:los-dev-secret-min-32-chars-change-in-prod!!}
    expiry-minutes: ${JWT_EXPIRY_MINUTES:15}
----

`JWT_SECRET` must be at least 32 characters. The default value is only suitable for local development. Set a strong secret for any shared or deployed environment:

[source,bash]
----
# Generate a secure secret
openssl rand -base64 32
----

See link:../security/authentication.adoc[Authentication] for how the JWT is used.

== Fineract Integration

[source,yaml]
----
los:
  deployment:
    environment: ${LOS_DEPLOYMENT_ENVIRONMENT:production}
  fineract:
    base-url: ${FINERACT_BASE_URL:https://localhost:8443}
    tenant-id: ${FINERACT_TENANT_ID:default}
    username: ${FINERACT_USERNAME:mifos}
    password: ${FINERACT_PASSWORD:password}
    mock-enabled: false
----

The REST adapter is used by default. `FINERACT_MOCK_ENABLED` accepts only the literal values `true` or `false`, case-insensitively; aliases such as `yes` and `no`, empty values, and other strings fail startup. Mock activation requires both the `dev` or `test` Spring profile and the matching deployment identity (`development` or `test`). For example, local development requires `SPRING_PROFILES_ACTIVE=dev`, `LOS_DEPLOYMENT_ENVIRONMENT=development`, and `FINERACT_MOCK_ENABLED=true`. The deployment identity defaults to `production`; production startup fails if the mock is enabled regardless of active profiles. Mock disbursement generates a fake loan ID and performs no operation against Fineract.

See link:../architecture/integration.adoc[Integration Architecture] for how these values are used.

== Scoring Weights

[source,yaml]
----
los:
  scoring:
    weights:
      income-ratio: 30
      debt-burden: 25
      employment-stability: 20
      repayment-history: 15
      loan-purpose-risk: 10
----

Weights must sum to 100. The application validates this on startup and fails fast if they do not. See link:../workflows/credit-scoring.adoc[Credit Scoring] for factor details.

== Approval Workflow

[source,yaml]
----
los:
  workflow:
    stages:
      - LOAN_OFFICER
      - CREDIT_COMMITTEE
      - BRANCH_MANAGER
    role-mapping:
      loan_officer: LOAN_OFFICER
      credit_committee: CREDIT_COMMITTEE
      branch_manager: BRANCH_MANAGER
    final-stage: BRANCH_MANAGER
----

Stages are sequential. `final-stage` determines which stage triggers the transition to `APPROVED`. Role mapping connects Fineract role names to LOS workflow stage names.

== Server Port

The backend starts on port **8082** by default:

[source,yaml]
----
server:
  port: 8082
----

Change this if port 8082 is in use on your machine.

== Environment Variables

[cols="2,3,2", options="header"]
|===
| Variable | Purpose | Default

| `DB_URL`
| PostgreSQL JDBC URL
| `jdbc:postgresql://localhost:5432/los_db`

| `DB_PASSWORD`
| Database password
| `sujan2003`

| `JWT_SECRET`
| JWT signing key (min 32 chars)
| dev default (unsafe for shared use)

| `JWT_EXPIRY_MINUTES`
| Token lifetime in minutes
| `15`

| `FINERACT_BASE_URL`
| Fineract API base URL
| `https://localhost:8443`

| `FINERACT_TENANT_ID`
| Fineract tenant identifier
| `default`

| `FINERACT_USERNAME`
| Fineract API username
| `mifos`

| `FINERACT_PASSWORD`
| Fineract API password
| `password`
|===

Never commit real secrets to source control. Use environment variables or a secrets manager for any value that is not a safe local default.
