== Overview

The LOS applies defense-in-depth: multiple independent controls each reduce a class of risk. No single control is relied upon exclusively. This document describes each layer, its current status, and where to find implementation detail.

== Authentication and Authorization

Authentication is handled by `JwtAuthFilter` and the dual filter chains in `SecurityConfig`. Authorization is enforced by Spring Security method security (`@EnableMethodSecurity`) and by `ApprovalWorkflowService` for workflow-stage role matching.

Details: link:authentication.adoc[Authentication] and link:authorization.adoc[Authorization].

== Input Validation

All request DTOs carry Bean Validation annotations. Spring Boot's `@Valid` binding triggers validation before any service code runs. A validation failure returns `400 Bad Request` with a structured error body listing each failing field.

The DTO classes in `org.apache.fineract.los.dto.request` use annotations including `@NotNull`, `@NotBlank`, `@Min`, `@PositiveOrZero`, and `@Size`. All queries use JPA named parameters — there is no string-concatenated SQL anywhere in the codebase.

== Tenant Isolation

Every entity table carries a `tenant_id` column. Every repository query includes `tenantId` as a WHERE-clause parameter. Services extract `tenantId` from the authenticated principal — never from user-supplied request fields.

**Pending PR (`feature/FINERACT-2442-updates-security`):** `JwtAuthFilter` will additionally validate that the `tenantId` JWT claim matches the `X-Fineract-Platform-TenantId` request header, returning `403 Forbidden` on a mismatch. Until this merges, tenant enforcement relies on the repository layer alone.

== Rate Limiting

**Pending PR (`feature/FINERACT-2442-updates-security`) — not yet in `main`.**

`RateLimitFilter` (Bucket4j + Caffeine) will apply per-IP token buckets:

* `/api/v1/auth/**` — 5 requests per 15 minutes (brute-force protection)
* `/api/v1/admin/**` — 20 requests per minute
* All other endpoints — 100 requests per minute

Exceeded limits return `429 Too Many Requests` with a `Retry-After` header.

== XSS Protection

**Pending PR (`feature/FINERACT-2442-updates-security`) — not yet in `main`.**

`XssSanitizer` (OWASP Java Encoder) will be applied at the service layer before persisting user-supplied text fields (comments, names, loan purpose, etc.), using `Encode.forHtml()`. This is a secondary defence — Angular's template engine sanitizes output by default, but encoding on the backend protects against stored XSS if the data is ever consumed by a different client.

== Security Headers

**Pending PR (`feature/FINERACT-2442-updates-security`) — not yet in `main`.**

The PR configures the following headers via Spring Security's `headers()` DSL and `StaticHeadersWriter` on both filter chains:

* `X-Frame-Options: DENY` — prevents clickjacking
* `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` — enforces HTTPS
* `Content-Security-Policy` — restricts resource loading to same origin
* `Referrer-Policy: strict-origin-when-cross-origin`
* `Permissions-Policy: geolocation=(), microphone=(), camera=()`

The PR replaces the previously deprecated `permissionsPolicy()` DSL call with `StaticHeadersWriter` (commit `1a3f181`).

== Transport Security

HTTPS is not enforced at the application level. In production, TLS must be terminated either at the application (Spring SSL configuration) or at a reverse proxy or load balancer in front of it. The `Strict-Transport-Security` header (pending PR) will instruct browsers to reject plain HTTP once HTTPS has been established.

== Secrets Management

All sensitive values are provided via environment variables with safe local defaults:

* `JWT_SECRET` — JWT signing key (must be at least 32 characters in any shared environment)
* `DB_PASSWORD` — PostgreSQL password
* `FINERACT_USERNAME` / `FINERACT_PASSWORD` — Fineract API credentials

`JwtSecretValidator` verifies the secret meets minimum length at startup and fails fast if not. Secrets are never logged. See link:../development/configuration.adoc[Configuration] for the full variable list.

== Audit Logging

`JwtAuthFilter` places `correlationId` into the SLF4J MDC for every authenticated request. The pending PR adds `tenantId` to MDC as well. Service layer code logs all state machine transitions (from/to state, application ref, actor) and all approval decisions (stage, decision, officer username) at `INFO` level. Authentication failures are logged at `WARN`.

Log output does not include passwords, JWT token strings, or full stack traces.

== Dependency and CI Security

|===

== Not Implemented

* Account lockout after repeated failed login attempts — rate limiting is the only brute-force control (and is pending merge).
* Token revocation — no blacklist; tokens remain valid until expiration.
* Refresh tokens.
* Multi-factor authentication.
* Distributed rate limiting — current implementation is in-memory per instance (Caffeine cache).
